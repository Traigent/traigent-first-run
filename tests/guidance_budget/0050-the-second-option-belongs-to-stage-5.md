Five of twelve blinded runs recorded a model option the agent does not have.
The agent reads one default and the runs declared two, naming a model that
appears nowhere in the file. The guide already forbade that in the same
sentence as it asks for the read - "an omitted parameter costs a few points,
an invented one makes the card wrong" - and it lost anyway.

It lost because it was arguing against a correct instinct rather than a
careless one. A baseline that compares one configuration against itself is
worth little, and an assistant that notices this is right to want a second
option. The guide's answer at that moment was only "do not", which leaves the
want intact and unanswered.

`GUIDE.md` already grants it: the enhanced run "adds meaningful non-model
settings by default, and tests up to 12 configurations from a materially
larger search space". The wish is the product's own plan, one stage later.
Nothing at the read said so, so the assistant had no way to know that waiting
costs the user nothing.

These bytes say it. Not another prohibition - a pointer to where the instinct
is satisfied legitimately, which is the difference between telling somebody to
stop wanting a thing and telling them when they get it.

The refusal added to `readiness.py` alongside this carries the same sentence,
because the two failures need different halves: the guide reaches an assistant
that has not yet invented anything, and the refusal reaches one that already
has.
