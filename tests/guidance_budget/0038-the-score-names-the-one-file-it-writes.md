The opening message told the customer that the score reads their project and
changes nothing in it. The same gate requires the row-level review to be recorded
in `traigent-runs/row-review.json`, so on any project with rows the sentence was
refuted by a single `ls`, and a blinded walkthrough produced exactly that: one
file written, into a project it had just promised to leave alone, and named
nowhere in what the user was shown. Nothing had ever compared the two rules.

Resident bytes buy the correction because the false sentence was resident. The
replacement keeps the claim the customer actually cares about - their agent,
dataset and evaluator are read and never touched - and adds the file this run
leaves behind. Naming it costs less than hedging it: a reader can check the whole
statement in one command, which is also how the defect was found.

The reference takes the rest, and it is the half that makes the file safe to
mention. A row review had no lifecycle: nothing said whether a later opening gate
replaces it, and the run plan that would explain why it exists is deliberately
withheld until the ask is answered, so a run that stopped at the ask - the state
this walkthrough ended in - left an unexplained artifact with no rule covering
it. Every opening gate now rewrites it whole, so answering the ask supersedes it
whether the answer keeps the dataset or points somewhere else, and no earlier
verdict survives to be read as a current one.

The remaining bytes settle `in_run`, which keyed on rows being drawn. A customer
who brings a split has settled which rows the run uses without this run drawing
anything, and the bounded subset is taken only above 100 usable rows, so on a
small brought split the literal reading leaves the flag off for the entire run.
Both readings passed validation and produced different cards - one reports how
many flagged rows the run reads and the other cannot say it - so a walkthrough
had to guess, correctly, on thirty rows. Drawn now means settled, with the state
that still leaves the flag off written down beside it so the rule cannot widen
into always setting it.
