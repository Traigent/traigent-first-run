# 0017 - a failed read is a question, not a ceiling

Entry 0016 bought the instruction to open the agent and write down what it can
already vary, and closed with one conditional clause: skip that work when there
is nothing to open. Read literally, "nothing to open" swallows an agent written
in another language, an agent compiled before this run saw it, and an agent that
lives behind a network call - none of which is an absent agent. A customer in
any of those positions was handed the unestablished-space ceiling as a verdict,
with a reason describing what nobody had supplied and no move they could make.

The correction needs prose because the module underneath it cannot help. Its
`AgentFacts` records whether a document or a reading arrived and holds no fact
about whether an agent exists, so a project with none and a project whose agent
resisted inspection are one state by the time anything is scored. Splitting them
in arithmetic would mean a new input, a new branch and a re-proof of the
ordering property; stating plainly at the gate that the reading is unconditional
wherever an agent turned up costs a few lines and removes the state instead.

The rest of the addition is the routing, and its length is the argument. Reach
and evidence are different things: failing to open somebody's file says nothing
whatever about their project, so the honest response names the file, requests a
settings document for it, rides on the question this run already puts rather
than adding another, and proceeds regardless if none returns. The ceiling is
kept and narrowed to the only caller it still fits - a direct invocation with no
human present to answer - and saying which caller that is takes a clause that
would otherwise be guessed at.
