Three hundred bytes into the one document that tells an assistant what to write into the build half,
and the reason is that four of its sentences described a scorer two merged changes ago. This is the
failure 0119 was written for, arriving in the same file one entry later, and 0119's own words say
why it keeps happening: the scripts carry no copy of these sentences, the byte budget does not read
English, and no contradiction registry knows the pair, so the change was invisible in the diff that
caused it because that diff touched neither document.

The reach sentence was the plainest. It said neither derivation leaves the selected callable's own
body, which is still true of control flow and has not been true of tools since the walk gained its
module hop - and the same file says so four hundred lines earlier, so a reader of one run met both
claims. Naming which derivation does which costs a clause and removes the disagreement rather than
softening it.

The acceptance sentence mattered more, because it is the definition an author acts on. "Whether each
declared tool can be found" describes reading the whole file, and reading the whole file is the
thing that only ever REFUTES a name - its own docstring says nothing is credited from it. An
assistant writing to that definition declares a tool the one-hop walk cannot reach and watches the
customer's pillar fall for a reason this guide had called fine, which is exactly the loss 0119
describes. The paragraph also refuted itself in consecutive clauses, since the very next sentence
already stated the reachable-share rule correctly.

And the scoring claim was the one the glossary had already been corrected for. "Keeps this check's
weight and earns nothing" is true of one function read alone and false of every route a customer can
take: supplying the knobs document rewrites all four signals as unmeasured, so the weight leaves the
denominator entirely and a `false` answer costs nothing at all. The customer-facing glossary has
said so since 0119. Two documents stating incompatible rules about one check is the defect this
repository keeps finding in its own history, and the fix is the same each time - correct the one
that is behind rather than reword both into something neither scorer does.

Last, the card's disclaimer denied the wrong thing. It listed a named tool being reachable among
what the read cannot establish, when reachability of a name is precisely what the walk now settles;
what stays unsettled is tool-hood, which the same file states correctly elsewhere. That is the shape
a merged script fix had already removed from the card itself - a clause introducing a finding about
reachability by denying reachability was checked - and the guidance kept the version the script no
longer matched.
