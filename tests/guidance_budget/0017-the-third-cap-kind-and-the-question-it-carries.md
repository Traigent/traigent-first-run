#203, stacked on #202. The scorer grew a third state some waves back and every
document that explains the taxonomy stayed at two, so a reader of this package
was told there is stopping and there is bounding, full stop. The state in
between is neither: nothing is broken, the comparison is worth paying for, and
a human still has to look at something first. Squeezing it into "stop" cancels
a paid run because an assistant did not like the look of somebody's rows.
Squeezing it into "bound" prints a ceiling with no way out, which is precisely
the shape that had to be repaired once already, one cap at a time, while the
prose kept describing the world before that repair.

Most of the bytes are not the taxonomy sentence. They are the thing the third
state exists to produce and never had. A flag whose only visible effect is a
slug in a JSON payload is not a remedy, so the middle kind is now written down
as a question with a stated place, stated contents and two named exits. What
rides on the halt in front of the first billed call is six items, each earning
its line because leaving any one out returns the reader to guessing - which
shortfall was found, what got dropped in its place, openable locations for both
files, the two rows at either end of the range so nobody judges the set by a
lucky middle, a plain statement of what the grader treats as right, and a fork
with two named exits and no quiet default. That last one matters most: agreeing
to spend has never been the same act as agreeing that the yardstick is yours,
and until now the guide let one stand in for the other.

Be exact about what this branch does and does not establish. Nothing here
executes that card. The scorer gained no code path that renders it, and the
tests added alongside read literal strings out of markdown and check one
ordering property of `recommended_action`; whether an assistant reading the
finished document actually stops and puts the fork is not something any of them
measure. What was bought is prose an assistant can follow and a reviewer can
hold it to, which is real and is less than a delivered question. An earlier
draft of this entry claimed the outcome instead, and claiming an unexecuted
outcome is the same defect as a card promising a remedy nobody prints.

Review then found the card firing on two unlike triggers with one set of
unconditional bullets, so a run that generated nothing was told to name a gap
it did not have and open a file it never wrote. Every bullet now carries its
condition. Review also found the only cap that asks already owning a complete
quoted question elsewhere, reached from stage 4 by name, disagreeing with this
card about when it is put, what it contains and what the answers are called -
so a user who settled it once met it again at the till. The rule is now one
question with one home: where a route already owns the wording, this card
restates the answer, and it asks only where no other home exists.

Placement follows the rule this repository already keeps. Everything expandable
sits in the safety reference beside the approval it belongs to; the flow file
gets the trigger, the pointer, and the one prohibition a reader might otherwise
invent for themselves, that this is extra content on a halt already scheduled
and not a fresh interruption. Six-sevenths of the new prose therefore never
enters the resident half at all.

Three smaller repairs come with it and cost almost nothing: the marketing page
stopped promising that nothing will ever be asked of the reader, the closing
card in the safety reference stopped guaranteeing a `proceed` verdict that an
asking condition legitimately overrides, and a comment in the scorer stopped
describing a card line the space-sized evidence sentence retired.
