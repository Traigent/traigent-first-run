Two prose defects fell out of a single re-run, and both of them are about a name.

The first cost an investigation into a run that had done nothing wrong. A folder
of readiness evidence was called `20260901T183000Z` and everything inside it was
saved about two hours after that, so the card it held read as a verdict taken on
a project that had not been assembled yet. Three documents wrote that path
segment three different ways, and exactly one of them ever said what such a
segment means - while defining a field inside a log file rather than a folder
name. Under guidance like that, a session minting a single identifier and
stamping every artifact with it obeyed the instructions precisely as well as one
putting the clock reading on each separate write. Both were available and nothing
chose between them.

These bytes buy the choice, and they buy it where the choosing happens. Both
places this guide puts such a name are in the document that never leaves context:
the folder is announced to the customer during the opening gate, and the rename
occurs in the paragraph refusing to resume. A rule for either that lived in a
reference would be met after the name had already been picked, which is not a
rule at all. So the sentence sits beside the earlier use, names all three spots it
governs, and the log field's row now points at it rather than carrying an answer
of its own. The scoring script is untouched deliberately: it declines to look at
a clock so that the twice-run container comparison stays identical byte for byte,
and the flag receiving the value now says which instant a caller is meant to hand
it, where before it only said where the value must not come from.

The second defect was a permission with no edge on it. One document told the
session to hand its settings observation of the program to each subsequent
scoring for as long as the work lasts. Another said an observation like that
describes its subject at one instant and is not paperwork to be filed and
submitted again later. Between them sits the paragraph where a session discards
its record and begins over, and that paragraph mentioned neither, which is how
one identical digest came to sit in two folders on opposite sides of a line the
work had drawn for itself, with every program line on both cards matching.

What earns bytes here is a boundary rather than a further prohibition. The
permission now attaches to the record instead of to the terminal, which is the
second job the word "run" had been quietly doing; and the retirement paragraph
says the folders left behind go historical alongside the record, so the fresh
first score looks at the program again. A first score resting on an observation
made before everything was thrown away is not a first score.

The last of it subtracts an imbalance instead of adding to one. A settings file
found lying around was already refused in three separate sentences, one carrying
a clause that neither a digest nor a stamp nor a filled-in list of wired controls
redeems it. Its twin, the observation of how the program is put together, had no
such sentence anywhere, although it is what supplies one of the three pillars. A
fourth refusal aimed at the twin would have been a fourth place to edit one
decision, so the earliest of the three now describes the family both belong to,
which is anything handed to a scoring that this work did not itself produce, and
the gate keeps its operating instruction while pointing upward for the reason.

The subtraction did not make that gate smaller, and an earlier draft of this file
said it did. Measured on the paragraph itself, it goes from 428 bytes to 526. The
restatement leaving is 63 of that, a pointer at the rule replacing it costs 60,
and the clause naming the twin's own folder costs 101, which nets to 98 more than
before. Those 98 are the part of this raise that the load-order case above does
not carry, because a sentence saying a folder proves nothing could sit in the
safety reference beside the rest of the settings-file depth and still be read in
time. It sits at the gate instead for a narrower reason: the belt-and-braces
clause it extends is already there, it is the sentence a run reads while deciding
what to hand the scorer, and splitting a two-item clause across two documents is
the seam this package keeps paying for. That is a judgement about where one
sentence reads best, not a load requirement, and it is worth saying which of the
two arguments each part of the raise rests on.
