The whole promise of this walkthrough is that what a customer already owns stays
separate from what the run supplies for them, and the score had that separation
for rows and for nothing else. A real agent, a real declared-collected corpus and
an evaluator written during the run reached ninety-three out of a hundred with no
ceiling at all, because every origin condition the scorer carried was scoped to
where the DATA came from. The marker was printed and the number did not carry it.

Two flags close that, and flags nobody is told to pass close nothing, so most of
what these bytes buy is the instruction to pass them. It sits beside the
evaluator-method rule because it is the same kind of state - resolved once,
updated the moment this run creates or replaces the component, and repeated on
every scoring call so a later card cannot quietly report a substitute as the
customer's own. It says explicitly that this is not a question for the customer:
the run wrote the file, so the run is the only party that knows, and asking would
be theatre.

It also says what omission costs, because omission is the failure mode here
rather than a wrong answer. Leaving a flag off scores a component this run
invented as though the customer had brought it, which is precisely the claim the
separation exists to refuse - and unlike a mistyped value, nothing about a
missing flag looks wrong on the card it produces.

The routing paragraph gains one sentence for the two new conditions, pointing at
the labeling rules that already own what may be said about generated material,
and stating that neither is a repair. Without it an assistant holding a ceiling
and a reason has no branch, and the likeliest invention is to treat a component
the run deliberately created as something to go and mend.
