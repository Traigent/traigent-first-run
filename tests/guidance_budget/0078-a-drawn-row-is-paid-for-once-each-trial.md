Five rules governed the bounded subset and none of them said the drawn rows
have to be different. On a file holding three hundred rows that resolve to six
questions, or forty whole-row copies among a few hundred originals, a compliant
draw could put the same question in the eighteen several times over. The run
plan records eighteen ids, the money approval prices eighteen, and twelve
trials buy two hundred and sixteen provider calls to observe far fewer outcomes
than that. Nothing in the package objected, because every existing rule was
about where the rows come from - which split, which band, recorded how - and
none was about whether any two of them are the same row.

Most of what a sixth rule costs goes on saying which readings of it are wrong,
because a rule that shrinks a paid draw is dangerous in the direction nobody
watches. Two rows asking one question under one answer are one row and the
second buys nothing. Two rows asking one question under different accepted
answers are one question and two rows, and both are drawn: dropping either
narrows what counts as correct, so a configuration that answered acceptably
would score exactly like one that answered wrongly. Questions set the size,
rows set the price, and the flow says both.

The identity is the other half and it decides money. The measure this package
already had keeps word characters and throws away every operator, so a file
asking whether a column is above five and whether it is below five hands it one
string. That is right for finding a leak between two splits, where seeing past
punctuation is the point, and wrong for a bound that deletes test cases the
customer wrote - on a walkthrough whose worked task is text to SQL, where the
discarded marks are the discriminating ones. The draw therefore has its own
identity with no false positive, and the rule names it rather than pointing at
a card key that answers a different question.

The population is named too, for the same reason and after the same mistake
twice. A count over every row in the file answers about held-out rows the draw
never touches; a count over every row on a side answers about rows carrying no
answer, which no comparison reaches. Both were live here, one on each axis, and
both proposed eighteen where twelve was the truth. So the helper returns the
scope beside the number and the finding prints it.

The cap is stated in both currencies, because the last spelling of it mixed
them. Eighteen is a row budget, the count it is compared against is questions,
and one `min()` over the two went out under a row label: a split of four
hundred rows asking two hundred questions was offered "eighteen usable rows"
for a draw that brings thirty-six, so twelve trials priced two hundred and
sixteen calls and bought four hundred and thirty-two. The finding now says the
questions and the rows they bring, and the rule tells an assistant to say both
wherever a run is priced.

The resident line moves because stage 6 named eighteen and priced "that
subset", which read as one number only while the two were always equal. It now
says the estimate is built from the rows actually drawn and that the draw can
come in under the default. The clause naming which shortage causes that is gone
rather than corrected: it sat in the file that owns pricing and named a
population settled elsewhere, and a conclusion routing to a reference must not
be able to carry that reference's mistake.
