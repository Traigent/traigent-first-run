Forty-four bytes to delete a carve-out and say why it is gone, and the reason it is worth an entry
at all is where the clause sat. Section 8 is the post-run verification - the list an assistant walks
before telling a customer the run succeeded - and one clause in it blessed a reduced baseline grid
"subject only to an approved disclosed reduction". The enhanced run has its own reduced-target
clause later in the same sentence, which is what makes the placement look deliberate rather than
slipped; it is the baseline half, before the semicolon, and it contradicts three other statements
and one assertion.

Section 6 of the same document says the reduction route is rows and never configurations, in those
words: the baseline grid is never reduced, a generated one runs its twelve and a preserved one runs
as the user defined it. The execution reference says it twice more and gives the argument - a grid
that does not run its whole space has ranked nothing - and its generated wrapper asserts the count
outright. So the verification step blessed a run the shipped code aborts, and an assistant reading
only section 8 would have approved one and reported it verified.

The customer-facing half is the worse half. Telling somebody their reduced baseline was verified,
when the document that owns the arithmetic says a partial grid has ranked nothing, is a claim the
run cannot support about the one number the whole comparison rests on.

The replacement does not merely drop the clause. It states the rule positively where the clause
stood and names the thing that was being got around: an approved disclosure does not make a reduced
grid whole. A carve-out removed silently is a carve-out somebody re-adds, because the next reader
meets a verification list with no explanation of why the obvious concession is missing.
