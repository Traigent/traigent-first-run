Seven hundred and thirty-two bytes of RESIDENT, which is more than this ledger usually approves for
one clause, and the reason is that it is a fifth thing the run's single question now carries. The
question already exists and already stops; what it did not do is ask the one thing the whole run is
about. A customer can optimize for anything the product supports, and this guide was the only piece
narrowing that to one word - silently, so nobody could disagree with a choice they were never shown.

The measured harm was an inversion rather than a preference. Declaring nothing, which is what the
guidance told an honest customer to do when no listed method fitted, scored the evaluation pillar 69;
declaring a comparison shape that was untrue scored it 100. Being honest cost roughly eleven overall
points, and the vocabulary was the whole reason: honesty had nowhere to go, so the honest answer
scored worst. Opening the vocabulary without opening the question would move the cost from the
mislabel to the silence.

Three rules land in the reference where they are read once. The key the run wires is the customer's
word, because an arbitrary name already travels through the objective, the metric function, the
result reading and the frontier - that was already written down, and this only stops `accuracy` being
typed out of habit over it. Cost is always the second objective, because it is measured identically
whatever the first one is and asserts nothing about the task. Accuracy is not, and that asymmetry is
the point: bolted onto a run optimizing tool-use compliance it reports a number describing nothing,
which is the same mislabel one layer out.

The default is kept and is now spoken. Where nobody named anything and the evaluator settles nothing,
accuracy and cost is still what runs - said in those words, so a default nobody chose stops reading
as a finding somebody made.
