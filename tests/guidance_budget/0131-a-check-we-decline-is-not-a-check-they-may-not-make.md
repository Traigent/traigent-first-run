One distinction the documents had collapsed, and every sentence written from the collapse.
`references/run-safety.md` said the evaluator check "is not made, so it earns nothing" - true of this
run and stated as though it were true of the world. traigent-first-run#506 is the finding that it was
not: a customer who measured their own evaluator on their own machine and handed the result to
`--calibration` was scored exactly as a customer who handed this run nothing, while a FAILING result
from that same source still convicted them. Same payload, same flag, opposite treatment, and the
recorded reason - "leniency bought by breaking the rule" - described a rule section 0 had already
withdrawn. This guide declines to PERFORM the check. It forbids the customer nothing.

Most of the spend is not the new rule. It is the disclosure script, which had been written for the
case where nothing was measured and said so in four places. `run-safety.md` instructs the assistant
to tell the customer "we therefore do not know whether their evaluator works" and "no step in this
guide would change that", and to "do not soften any of it" - both false of a run whose own result was
counted, and both are sentences the card itself stops printing in that state. Those clauses are now
conditional on no result having reached the score, with the replacement said beside them.
`evaluation-and-dataset.md` carried a second copy of the half that went false and it was falsified in
lockstep, which is the ONE HOME rule's own cost demonstrated: it now delegates that half and keeps
the sentence it actually owns - that what is missing is evidence and not a finding against their
evaluator, which a test pins to that document and away from `run-safety.md`. Deleting that one too
was a first draft's error, caught by the same test: the copy to remove is the one that duplicates,
never the one the rule lives in. The run-log vocabulary and the customer glossary carried the same
assumption a level down and are corrected the same way.

The most expensive correction is the one that looked like a convenience. A first draft told the
assistant to pass the project's result INSTEAD of `--calibration-scope-refused`, because the two
flags refused each other at the CLI. Measured, that instruction traded the entire execution
disclosure for the credit: on a project whose walk found no engine, the declaration is the only thing
that raises `evaluator-calibration-refused`, so the card went from 45 with the hazard, the connection
question and the ceiling to 85 STRONG with no cap at all. The flags no longer refuse each other -
they stopped being opposites when `--calibration` stopped meaning "the result of executing it HERE" -
and the guidance says to pass both. That is the state that is true, and it scores as both: the pillar
counts the result, the card still says what the paid run will do, and the 45 stands because nothing
this run read established what the evaluator reaches.

Also corrected here because the route made them load-bearing: "never reuse a result from an earlier
run or a pre-existing artifact" now says which calibrations it means, since the one route this entry
adds is a pre-existing artifact by construction and the rule sat ten lines above it; and two claims
that the containment review is "the only route to the calibration evidence itself", which was never
true of the customer, only of us.

The provenance clause is new and it is SYMMETRIC, which is the part worth recording. This score never
runs a calibration; every payload it reads arrived from something it did not watch, and that was
already true in the ordinary arm and said nowhere. Naming it only where the shape is refused would
have marked the self-supplied result as the unverified one while an identically unverified payload
two arms over said nothing at all - which reads as though the ordinary one had been observed. The
clause is the same in both arms and on both verdicts, because the fact is.

And the objection the withdrawn reason was right about is recorded at the site rather than answered
away. The customer broke no rule; an assistant that ran this check from inside the guide did, and
this score cannot tell the two payloads apart, because both arrive as JSON on one flag. Crediting the
result therefore does pay for the forbidden route. The answer is that preventing it is not the
scorer's job: `calibrate_evaluator.py` refuses an evaluator that executes the candidate's answer,
naming the file and the line, for the shapes its walk can see - and this file says twenty lines above
that finding none establishes nothing, so the residue is the same population the refusal has never
been able to reach. A scorer that withholds credit to enforce a rule reports a lower number than it
believes, which is the accusation 0130 has just finished removing from this same cap.
