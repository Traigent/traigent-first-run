Three and a half kilobytes, and the reason is that the rule this file opens with named one way a run
may stop and the file then defines four. A review measured every hard stop against section 0's own
ownership test and three failed it - not because the stops are wrong, but because the test had no
category they could pass in. A rule that classifies sound stops as violations is worse than no rule,
because the next person applying it removes a gate that was doing real work.

So the carve-out gains the three categories it was missing. An action we refuse to take ON their
machine is not a check we declined to make FOR them: one costs a measurement and the other would
cost them their computer, and only the first is what the corollary is about. A broken instrument is
the one stop the standing rule makes stricter rather than looser, because "proceed on disclosure"
assumes the run can still measure something, and a stack contradicting its own contract is a run
that cannot - continuing there does not produce a worse number, it produces a number that cannot
mean anything and then bills for it. And an obstacle that is neither party's existed all along with
nowhere to be written down, which is how a provider's silence came to read as the customer's fault.

The dependency stop stays and stops apologising. It refuses a source build because a source build
runs the package's own setup code on somebody else's computer, and the honest shape of that refusal
is a route rather than a number: which package needs building, and the two things they can do about
it. Nothing is deducted and no claim is bounded, which is what separates it from the evaluator gate
two sections up.

The cost stop becomes an ask, and the size of the exposure is what makes that defensible rather than
reckless. Neither cost nor usage came back, so no action of theirs makes the call observable and no
refusal of ours caused it. Section 0 already carves out spending without approval, so approval is
exactly the instrument this needs; and the stage it guards runs over the walkthrough's small dataset
under a ceiling already agreed, so what they are being asked to accept is bounded and they can weigh
it. Default stop, their approval proceeds, silence does not, and every affected call is marked
untracked so the summary says which numbers nobody can reconcile.

One sentence went the other way, on measurement. The dependency bullet preferred "a fully pinned,
hash-checked requirements file" and this package pins hard - `traigent==0.26.0` and two more, with
the guidance twice refusing an unversioned install - but ships no hashes at all. The pin half was
already true and stays unsaid here because the bullet below states it; the hash half described a
regime nothing in this repository follows, so it is gone rather than aspirational. A preference
nobody implements reads as a control to the next auditor.
