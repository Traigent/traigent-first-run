The unusable branch offered three routes: repair the customer's files in a
reversible copy, write clearly labelled stand-ins, or pause. The first two are one
action. The assistant opens their file either way, keeps whatever holds up, and
writes the rest; where nothing holds up - an echo stub with no call path, a scorer
returning one number with no rubric - both produce the same artifact, in the same
directory, under the same marker. The customer was being asked to choose between
two names for identical work at the moment they decide what to spend.

Two blinded runs collapsed it, independently, and both were right. The second was
graded a failure for doing so. That is the reading this entry buys: a rule two
careful readers refuse in the same way is not being misread.

The document already owned the argument. Its gap section refuses a third route in
almost these words - whether the run derives from something or from nothing "is a
fact this run already established, so offering both would be asking the user to
pick a situation rather than an action" - and the unusable section then did that
exact thing one heading later. Applying the existing principle consistently is
most of this change, which is why the reference grew by less than the reasoning
behind it would suggest.

What survives is not deleted but moved. How much of the customer's material lives
through the build still decides whether the result reads as theirs or as
walkthrough material, and that sentence is now a disclosure inside the build
route rather than the thing separating two routes. It is a consequence the run
computes from files it has already read, so a customer cannot pick it and should
not be asked to.

The count is now derived rather than declared, and the bytes that say so are the
ones that stop this reopening. A limited component still executes, so continuing
on the customer's own material is a real action and earns a third route in the
dataset reference; an unusable one cannot be continued on at all, so the third
route has nothing to be. Without that stated, the two documents read as a
contradiction and the next reader repairs the wrong one.

The last bytes mark the recommendation. Two routes with nothing marked is a menu,
and this guide already holds that a menu offered instead of a recommendation is
no recommendation; the dataset reference marks its repair route for the same
reason. A blinded run reaching the unmarked pair supplied "(recommended)" itself,
which is what an unstated default looks like from outside, and the rule about
stating a thing so silence never has to be interpreted is one section away.

The final bytes answer three things a reader supplied wrongly on their own. The
marker is drawn as tools and means a generated substitute, so a customer decoding
the glyph unaided reads "repaired" - the one thing it never means - and the ask
now says it in words. "Your rows" is heard as all of them, and above 100 usable
rows the paid run reads a bounded sample, so the count this project will really
use is named rather than implied. And the first run is bounded whichever route is
taken: pausing to fix their own components buys a better-grounded result, not a
bigger one, and silence there sells the pause on a promise this walkthrough does
not make.
