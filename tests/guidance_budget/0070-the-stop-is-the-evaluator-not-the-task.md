# 0070 - the stop is the evaluator, not the task

A customer whose project does natural language to SQL was told their task was
out of scope for this guide, and the run stopped before building anything. The
claim was false, and false in a way no reviewer could see from the diff that
wrote it: the readiness script has always carried `code-sql` among its declared
task kinds, offers it on `--task-kind`, and prints "composite suits code-sql
output" when the declared ruler fits. What is genuinely refused is an evaluator
that executes the answer, and that refusal had been written into a table row
whose subject is the answer shape rather than the scorer grading it.

Two limits had been collapsed into one sentence, and these bytes separate them
in the six places the collapse reached. The costliest place is the one an
assistant reads first. The authorization row that refuses an executing call path
is resident, in context from the opening turn; the depth behind it is not, so at
the moment a run decides to stop, the refusal is loaded and its boundary is not.
Seventy-four resident bytes put the boundary beside the refusal, and forty-five
more widen the routing sentence that had illustrated an evaluator limit with
three task families - which is why this raises both ceilings and not only the
total.

Most of the reference spend buys a route that actually scores, which the first
draft of this change did not. Removing a refused method from the selection table
left two replacements behind, and both fail the mandatory four probes this same
document defines: comparing the answer as text scores a correct query carrying a
different alias zero on `equivalent_good`, and a parser gate on its own scores
every syntactically valid query one, failing `bad_fails` and `non_constant`. So
the row now names the method value to pass and the canonicalization that makes
it pass - measured, not asserted, on both branches and on the replacement. It
also says what a canonical form does and does not reach, because the author who
is not told picks the `equivalent_good` probe that decides whether their own run
is blocked, and the cheap answer to a red gate is to widen the scorer until it
goes green.

The rest is depth. The semantic-coverage row names the failure axes a review of
a query answer covers, in the register its five sibling rows use, where before
it named no axis and was the one answer shape the inventory had nothing to say
about. The section owning the stop states its own edge and defers the choice of
ruler to the document that owns rulers.

The vocabulary line is worth its cost because of where it is read. The glossary
loads on demand at the moment of explanation rather than at a stage, so nothing
guarantees the corrected selection table is in context beside it, and its own
rules say a decision the user must make is phrased from its entry. Its list of
evaluator kinds was the menu a customer picks from, and every route on it either
ran the answer or missed the one that scores.

Two smaller repairs ride along because the same collapse produced them. The
component note now says the recommended demonstration task is a default for a
user with nothing to anchor on rather than a list of what is supported. And the
route out for a genuinely executing scorer is named again in prose: its only
hyphenated spelling had lived in the deleted cell, leaving a pointer elsewhere
in the package with nothing to land on. Bands, weights and thresholds are
untouched; one `fits` entry is added so that no task kind is left with the
refused call path as its only well-rated ruler.
