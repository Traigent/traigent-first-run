# 0042 - a comment is not a knob

follows: 0041
total-ceiling: 366_009
total-measured: 365_609

A blinded run recorded six names into the agent read that appear only in a
comment. The stub's comment says those settings "would shape the real provider
call"; nothing in the call path reads any of them. The score survived - the caps
and the band were right, because names without values establish nothing - but the
card then explained a search space the project does not have.

The contract said knobs are "what the agent can be told to do differently", which
a comment naming six settings satisfies on a charitable reading. So the rule had
to be derived, and the tell that it was unstated is in the transcripts: two runs
derived it correctly and wrote the derivation out in prose, unprompted, as though
answering an objection. A third derived it wrongly.

These bytes state it. A name appearing only in a comment, docstring, TODO or
example is not a knob; record one where executable code reads it, passes it
onward, or selects behaviour from it.

The reason travels with the rule because the reason is what generalises. Recording
comment names reports a search space this project does not have - the same false
readiness a historical config-space document produces, arriving through the one
input that is supposed to be read fresh from the source. The guide already guards
that error on the config-space route and left it open on the agent-read route,
which is why stating the prohibition once, in the section that owns the agent
read, is the whole fix.

Resident does not move: the agent-read contract lives in the reference, and the
flow already mandates the read.
