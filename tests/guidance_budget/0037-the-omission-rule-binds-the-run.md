# 0037 - the omission rule binds the run, not one invocation

follows: 0036
follows-total-measured: 356_289

The rule excluding a pre-existing config-space document was phrased as something
the opening and stage-4 calls do: omit the file here. A blinded walkthrough obeyed
that exactly, then issued a fifth scoring call over the same file, labelled it a
harness-side counterfactual never shown to the user, and quoted its output among
its own findings - the agent pillar at 41 rather than 12, and the blocking cap
gone. Nothing in the wording forbade the extra call, because the wording governed
what four commands were passed and not what the run was permitted to execute.

The reported score was right, which is why this earns bytes rather than a smaller
correction. No verdict moved. What appeared was a second and higher figure printed
beside the real one, derived from precisely the input the exclusion exists to keep
out, with a sentence beneath it explaining that the higher figure is what the
project would score if the file counted. The claim the exclusion protects is that
the opening number reads this project as it stands today; an alternative published
next to it defeats that claim without altering a digit of the score itself.

The label is the second half of the defect. "Never shown to the user" was accurate
about the rendered card and untrue of the evidence directory, which is where a
captain triages, a reviewer reads, and a later run goes looking for prior
measurements to cite. Treating the card as the boundary of what has been published
is available to any future run that wants a number it has been told not to take,
so the correction names the bundle rather than the screen.

These bytes also close the door the first sentence left ajar. A read-only
invocation writes nothing to disk and therefore reads as free; its cost is that
its output becomes evidence the moment it is recorded. The guide already refuses
the symmetric move at the other end of the run, where a close may not be delivered
on a second number, so what is added here is the missing half of a rule this
package keeps rather than a new demand on the reader.
